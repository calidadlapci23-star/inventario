# Blueprint: Laboratorio de Inventario\n\n## Visión General\n\nEste documento describe el plan de desarrollo para la aplicación de inventario de laboratorio. La aplicación está diseñada para gestionar reactivos y suministros, optimizando el seguimiento del stock, las fechas de vencimiento y el consumo.\n\n## Diseño y Estilo\n\nLa aplicación sigue una estética limpia y profesional, con un diseño adaptable a dispositivos móviles.\n\n- **Tipografía**: Utiliza la fuente `Inter` para una excelente legibilidad.\n- **Paleta de Colores**:\n  - **Fondo**: Gris claro (`#F9FAFB`)\n  - **Primario**: Azul para enlaces y botones de acción.\n  - **Alertas**: Amarillo para advertencias (stock bajo) y Rojo para alertas críticas (vencimiento).\n  - **Contenedores**: Blanco con sombras suaves para un efecto \"elevado\".\n- **Iconografía**: Incorpora iconos de `lucide-react` para mejorar la usabilidad.\n- **Layout**: Diseño basado en tarjetas para presentar información y acciones de manera clara y organizada.\n\n## Características Implementadas\n\n### 1. **Estructura de Navegación y Páginas Base**\n- **Layout Principal (`app/layout.tsx`)**\n- **Página de Inicio (`app/page.tsx`)**: con enlaces corregidos a las funcionalidades.\n- **Página de Recepción (`app/recepcion/page.tsx`)**: Contenedor para el formulario.\n\n---\n\n## Plan Actual: Expansión del Formulario de Recepción\n\nBasado en la solicitud del usuario, el formulario de recepción se expandirá para incluir un conjunto completo de campos, transformando el formulario simplificado en una herramienta de entrada de datos detallada.\n\n### 1. **Actualización del Componente del Formulario (`app/components/RecepcionForm.tsx`)**\n- **Objetivo**: Añadir todos los campos requeridos para un registro de recepción completo.\n- **Directiva**: Continuará siendo un Componente de Cliente (`\'use client\`).\n- **Nuevos Campos a Añadir**:\n    - `Disciplina`: `Select` (Dropdown).\n    - `Producto`: `Input` de texto (preparado para futuro autocompletado).\n    - `Categoría`: `Select` (Dropdown).\n    - `Proveedor`: `Input` de texto.\n    - `Unidad de Medida`: `Select` (Dropdown).\n    - `Alerta Mínima`: `Input` numérico con texto de ayuda.\n    - `Ubicación en Almacén`: `Input` de texto.\n    - `Observaciones`: `Textarea` para notas adicionales.\n- **Datos de Ejemplo**: Los campos `select` (`Disciplina`, `Categoría`, `Unidad de Medida`) se poblarán con datos de ejemplo temporalmente.\n- **Lógica de Envío (Sin cambios por ahora)**: Para evitar errores, la función `handleSubmit` continuará enviando solo los campos que la API (`/api/recepcion`) ya procesa (`producto_id`, `numero_lote`, `cantidad`, `fecha_recepcion`, `fecha_vencimiento`). La integración de los nuevos campos en el backend será un paso futuro.\n
